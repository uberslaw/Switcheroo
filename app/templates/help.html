Using Switcheroo

Internal Client Services / Networks desk for Catalyst 9300 access ports. Writes wait for Networks unless an auto-approve policy matches.

Client Services

  • Open Switches, pick a box, click a port on the faceplate.
  • Request a VLAN change, bounce, or no-shutdown from the right-hand pane. That queues a request — it does not hit the switch until Networks approves.
  • On-demand refresh is shared per port (60s cooldown) so two people cannot stampede the same interface.
  • Troubleshooting mode polls one port for five minutes, then stops.

Networks

  • Approvals (and the Requests page) accept or reject queued writes.
  • Teams cards include I'm on it so two people do not work the same VLAN request.
  • Inventory is where you add real Catalysts, pause monitoring (stops 60s/daily/on-demand polls without deleting), and delete lab simulators before live testing. Delete only removes the row from Switcheroo — it does not change the switch.
  • Access is CS permissions. Device passwords are stored encrypted. Do not paste production TACACS into a shared lab box.

Launch Control and diagnostics

On Windows, open scripts\Switcheroo-LaunchControl.cmd (Start / Stop / Restart, live console, log folders). If something fails, click Diagnostics ON, reproduce the action, then open data\diagnostics.log. Each hop logs begin/ok/fail so you can see whether RESTCONF, SSH, Teams, or ServiceNow died. Turning diagnostics off is enough while the process is up; a restart is only needed if the site is down.
